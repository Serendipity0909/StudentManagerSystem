## A. 纯函数计价（`App.ContractsCore.priceContract`）

计价接口签名（读码确认）：`priceContract({year,grade,planName,plan:{unit_price,stages[],discount_type,discount_value}, subjects:{A:[…]}, discount:{type,value}, balance})`
→ 返回 `original(O) / discountAmount / tuition / materialAmount / subtotal / deduction / payable / balanceLeft / subjectRows / stageMaterial / ok`。

公共夹具（我自建）：`unit_price=240`，`stages=[{A,7次,资料100},{B,18次,资料100}]`。

### A1 Excel 算例（1 科数学 / 减免 300）→ 通过

```
输入 unit_price=240  stages=[A 7次/资料100, B 18次/资料100]  每阶段 1 科(数学)  优惠 amount 300
输出 O=6000  M=200  T=5700  S=5900  应付=5900  科目行=[["数学",25,6000]]
```
`O=240×7×1+240×18×1=6000`、`M=100+100=200`、`应付=6000−300+200=5900`。✅ 三项全对。

### A2 2 科算例（减免 700）→ 通过

```
输入 每阶段 2 科(数学/英语)  优惠 amount 700
输出 O=12000  M=400  应付=11700  科目数=2
```
`240×7×2+240×18×2=12000`、`M=400`、`12000−700+400=11700`。✅

### A3 各阶段科目数不同（最易实现错的一条）→ 通过

```
输入 A 报 1 科(语文)、B 报 2 科(数学/英语)
输出 O=10320  M=300  stageMaterial=[["A",100,1,100],["B",100,2,200]]
```
`O=240×7×1 + 240×18×2 = 1680 + 8640 = 10320`，**不是** `240×25×2=12000`。✅
实现确实是「逐阶段 `单价×该阶段次数×该阶段科目数` 再累加」（`js/module-contracts.js:376-384`），与用户原文口径一致。

### A4 跨阶段同科目合并 → 通过

```
输入 A:数学  B:数学+英语
输出 科目行=[{数学,hit:[A,B],25次,6000},{英语,hit:[B],18次,4320}]
```
数学只有一行、次数 25、小计 6000。✅ 科目行数 2（不是 3）。

### A5 只报单阶段科目 → 通过

英语只在 B：`次数=18`、`小计=4320`（`240×18`）。✅

### A6 折扣只作用课时费 → 通过

```
输入 85 折（discount {pct, 85}）
输出 O=6000  T=5100  disc=900  M=200  S=5300
```
资料费 `M` 没缩水。✅

### A7 优惠金额 > 课时费 → 通过

```
输入 amount 7000（课时费只有 6000）
输出 O=6000  T=0  应付=200
```
课时费截断为 0、应付正好等于资料费、无负数。✅

### A8 结余 > 应付 → 通过

```
输入 balance=10000（小计 6200）
输出 S=6200  抵扣=6200  应付=0  剩余=3800
```
抵扣封顶=小计、应付 0、余额不出负数。✅
（说明：我初稿把 `6000+200` 误算成 6100，是我的错，已按 6200 修正期望后通过。）

### A9 浮点取整 → 通过（**未出现 toFixed 截断**）

```
输入 unit_price=1234.50  A 7次+B 18次=25 次  每阶段 3 科  85 折
输出 O=92587.5  T=78699.38  M=600  S=79299.38
```
`92587.5×0.85=78699.375` → half-up = **78699.38**（`toFixed(2)` 会给 78699.37）。
另外我全量搜过 `js/module-contracts.js`：**该文件里 0 处 `toFixed`**，金额展示统一走 `App.UI.money`（内部先 `round2` 再 `toFixed` 只用于字符串化），计价链路无截断风险。✅

### A10 空科目 / 空阶段 → 通过（被 validate 拒绝）

```
validateContract(subjects {A:[], B:['数学']})        → "A 阶段至少选择 1 科"
validateContract(两个阶段都空)                        → "A 阶段至少选择 1 科"
validateContract(方案 stages=[] )                    → "该年份年级还没有价目方案，请先到『价目维护』新增"

priceContract(空科目) → ok=false, payable=0
```

### A 段追加的对抗性探针（全部通过）

- **A11 方案外阶段选了科目**（方案只有 A，科目里却塞了 B）：`"该方案只包含 A 阶段，请清空 B 阶段科目"` —— 不会把 B 阶段偷偷算进只有 A 的方案。
- **A12 负结余绕过前端直接调 priceContract**：`balance=-500 → 抵扣=0、应付=小计 6200`，不会算出负抵扣。
- **A13 云端重复行**（并发写入中间态，`findPlan` 的确定性选择）：`updated_at` 较新者胜出；同刻取 `id` 较大者 —— 实测 `unit_price=200`（新）与 `id=7`（大）胜出。✅

## 观察项（非阻塞，供你决定是否修）

1. **折扣输入框 `step=0.1` 与「百分数必须整数」的校验口径不一致，且提示词不精确。**
   方案表单与合同表单的折扣输入都是 `min=1 max=100 step="0.1"`（`js/module-contracts.js:1125`、`1765`），
   但 `parseRate` 只接受 1–100 的**整数**百分数。实测输入 `88.5` → 被拒，提示却是
   `折扣需在 1–100 之间（如 85 表示 85 折）` —— 而 88.5 确实「在 1–100 之间」，用户会困惑。
   建议：要么把 `step` 改成 `1`，要么把文案改成「折扣请填 1–100 的整数（如 85 表示 85 折）」。
   **不影响数据正确性**（拒绝是对的，只是话没说清）。

2. **`docs/ddl-v2.sql` 中 `contracts.items` 的行内注释仍是旧格式**：
   `items jsonb NOT NULL DEFAULT '[]'::jsonb,  -- [{stage,subject,unitPrice,sessions}]`
   T9 实际快照已是 `{planName, plan, stages, lines, subjectRows, stageMaterial, pricesVersion}`。
   纯注释，不影响运行；但会误导后来人（我复验时先被它带偏了一下）。

3. **无优惠时明细单显示「优惠（无优惠）」且金额打印为 `－0.00`**：
   ```
   课时费原价合计（O）| 1680.00
   优惠（无优惠）     | －0.00      ← 读起来像「减 0.00」
   折后课时费         | 1680.00
   ```
   建议无优惠时该行金额显示 `0.00` 或 `—`。纯文案。

4. （记录，非问题）`pct=1`（100 折）文案输出 `10折`，符合中文习惯，正确。
5. （记录，非问题）各阶段资料费不同时，资料费行单价列并列显示 `100.00 / 250.00`，属预期设计。
