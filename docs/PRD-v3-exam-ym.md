## 1. 变更目标

**一句话：** 让「考试实际发生的年月」取代「录入时间」成为成绩排序与对比的唯一依据，解决补录导致的月份倒置与跨年错序。

三个目标（正交）：

1. **顺序正确**：先录 11 月、后补录 10 月，趋势图仍按 10 月 → 11 月展示，结论方向正确；跨年按年+月数值先后。
2. **口径统一**：成绩总表、考试下拉、班级统计、班级分析、分析报告「四、趋势」、历史趋势图共用一套排序键，消除现有三套割裂口径（录入时间 / 中文文本序 / `entered_at`）。
3. **数据零损**：42 行既有成绩的**既有 16 列值一字不改、行数不增不减、唯一索引不变**（G1 红线）。

## 4. 字段与校验口径表

### 4.1 字段定义与唯一键决策

| 项 | 定义 |
|---|---|
| 云端列名 | `exam_ym` |
| **内存字段名** | **`r.examYm`（camelCase，全站唯一叫法）**。云端 `exam_ym` ↔ 内存 `examYm` 的映射**只发生在 `sync.js toRow / fromRow` 两处**；其余代码（core.js / module-* / analysis / locator / charts / export）**禁止出现 `r.exam_ym`** |
| JSON 备份字段 | `records[].examYm`（`backupJSON` 整对象透传、`normalizeRecord` 白名单恢复） |
| 类型 | 可空 TEXT，`YYYY-MM`，例 `2026-10` |
| 默认值 | **无数据库默认值**；新建记录由录入窗体按当前本地年月（`Score.defaultExamYm()`）填入 |
| 严格格式 | 严格 `YYYY-MM`：4 位年份 + 补零月份 `01`–`12`（正则见下方注）；不匹配 → 视为「缺年月」并标「年月异常」，**不阻断读取、不自动改写** |
| 必填 | **新建必填**；编辑已有记录时若为空也必须补齐后才可保存 |
| 是否入唯一键 | **否**（D3） |

> 格式正则：`/^(\d{4})-(0[1-9]|1[0-2])$/`

**D3 决策理由（不纳入唯一键）：**

- 用户诉求是「排序」，不是「区分同名两场考试」；纳入年月不改变排序正确性，只改变覆盖语义。
- 纳入需重建云端唯一索引（生产表、42 行在线），并同步改前端 5+ 处：`Score.key` / `Score.delKey` / `sync.js rowKey` / `delKeyOf` / 删除队列 / `export.js` 备份合并逻辑；还会让「补录时改了年月就插出第二条」取代现有的「重复录入自动覆盖」习惯，风险面远大于收益。
- **由此带来的语义（必须写进 UI 提示）**：同一 `姓名+学校+班级+同名考试` 永远视为同一次考试，重复录入仍走 upsert 覆盖。**跨年若两场考试同名，必须在考试名称中自行区分**（如「2025年10月段考」/「2026年10月段考」）。
- **新增的覆盖确认口径**：保存时（`submit()` 内、调 `Score.upsert` **之前**）若命中同键已有记录、且 `String(hit.examYm) !== String(rec.examYm)` → 弹确认：「已有同名考试记录（考试年月 YYYY-MM），继续保存将覆盖该记录。若这是另一场考试，请返回并修改考试名称（建议加年份）。」按钮 `覆盖并保存` / `返回修改`；选「返回修改」**不产生任何写入**（不调 `Store.save()`）。

> **架构裁决（ARCH-v3 §0 D3，已闭环）**：`software-architect` 复核线上代码后**同意 A**，且**不升级 team-lead 走 B**。补充依据：唯一键散落 6 处（`Score.key / delKey`、`rowKey / delKeyOf / delCidOf`、`restoreJSON` 同键合并），其中 `delKeyOf` 硬编码 `split(SEP).slice(0,4)`，纳入年月会连带破坏删除队列解析；B 还会把「重复录入静默覆盖」变成「改年月插第二条」，与 V-B3 覆盖确认直接冲突。B 的迁移路径仅在 ARCH-v3 预留，**唯有用户明确要求「同名跨年两场考试必须共存」时才启用**（见 §9 OQ-1，状态为「已裁决」）。

### 4.2 录入窗体两个下拉

| 控件 | 类型 | 选项 | 默认值 | 必填 |
|---|---|---|---|---|
| 考试年份 | `<select name="examYear">` | 当前年 − 5 ~ 当前年 + 1，共 **7 项**，倒序或正序固定为升序 | 当前本地时间年份 | 是 |
| 考试月份 | `<select name="examMonth">` | `1月` ~ `12月`（value `01`~`12`） | 当前本地时间月份 | 是 |

- 年份范围随系统时间动态计算（如当前 2026-11 → 2021 ~ 2027）；默认值来源 `Score.defaultExamYm()` 用**本地时间** `new Date().getFullYear() / getMonth()+1`，禁止 `toISOString().slice(0,7)` 取 UTC。

- 备份恢复 / 外部直写带范围外年份时：读取保留原值、标「年月异常」；编辑时下拉**自动扩展**把该年份加入选项，不强迫用户改成合法值。

### 4.4 历史数据一次性回填口径（42 行）

```
对每一行云端 exam_ym IS NULL 的旧记录（SQL 侧，非前端）：
```

### 4.5 字段贯穿清单（5 + 1，含 `undefined` 语义）

> **统一约定（ARCH-v3 §1.3）**：内存侧只认 **`r.examYm`**；云端列 `exam_ym` 只在 `toRow / fromRow` 出现。`examYm` 缺失或非法时一律为 **`undefined` / 原样脏值**，**不得填 `''`**。原因见下方「致命风险」。
>
> **⚠ null-safe 强制约束（§0 D-2）**：所有 `examYm` 的「有/无」判据一律用 **`== null` / `!= null`**，**禁止只判 `=== undefined` / `!== undefined`**。手工编辑过的旧 JSON 备份可能带 `examYm: null`——`null !== undefined` 为真，`toRow` 若按 `!== undefined` 判断就会写 `exam_ym: null`，把云端 42 行已回填年月清空；`fp` 若按 `=== undefined` 则把 `null` 编成 `'null'` 指纹而非 `''`，行为漂移。下表 #1 / #3 判据已按此约束书写。

| # | 环节 | 要求 |
|---|---|---|
| 1 | 保存（`sync.js toRow`） | **条件带上（null-safe）**：`if (r.examYm != null) row.exam_ym = r.examYm;`。**不得无条件写 `exam_ym: ''`**——JSON 序列化会丢弃 `undefined` 键，PostgREST update 因此不会动该列。注意 `toRow` 每次写入都无条件刷新 `updated_at: now / last_editor: me()`，这是**既有写穿行为**、与是否条件带上 `exam_ym` 无关 |
| 2 | 读取（`sync.js fromRow`） | `examYm: (row.exam_ym == null) ? undefined : String(row.exam_ym)` —— **容忍旧行缺列**（已 null-safe）。**脏值原样保留**：`2026-1` 这类值必须原样进内存，由 UI 判「年月异常」（V-2 / V-D3），**禁止在此处补零或纠偏** |
| 3 | 变更指纹（`fp`） | `[...原 7 项, r.examYm == null ? '' : String(r.examYm)]`（**null-safe**：`null` 与 `undefined` 同归 `''`）；漏了会导致「只改年月不推送云端」，本地看似生效、刷新即回退（V-E7） |
| 4 | 冲突回滚快照（`snapState`） | 增加 `examYm: r.examYm`，保留 `undefined` 语义 |
| 5 | 回滚还原（`restoreState`） | 增加 `r.examYm = s.examYm;`（**含 undefined**）；漏改 = 23505 冲突回滚时年月退回旧值 |
| +1 | 备份恢复白名单（`export.js normalizeRecord`） | `examYm: (r.examYm == null) ? undefined : String(r.examYm)`：备份有值就恢复（V-F2），备份无值保持 `undefined`（配合 #1 不清空云端）。**不要写 `examYm: ''`** |
| 附 | `core.js Score.newRecord` | 增加 `examYm: undefined` 占位；录入窗体 `submit()` 经 `Score.makeExamYm()` 赋值 |
| 附 | `core.js Score.upsert` | 命中已有记录时**继承/保留 `examYm`**（同 `id/ts/_cid/_by` 继承模式）；`Score.key` 4 字段构成不变，`record.mod` 与「保留 ts」行为不变 |
| 附 | `core.js` 新增纯函数 | `defaultExamYm / makeExamYm / examYmOf / examOrderKey / sortByExam / examCmp / examYmLabel / examAxisLabels`（全站排序唯一真源） |
| 附 | `app.js genDemo` | 3 场示例考试显式填 `examYm`（按本地当前年月往前 2/1/0 月递增）；`rec.ts` 生成逻辑不变 |
| 附 | JSON 备份（`backupJSON`） | 现有实现导出整对象，`records[].examYm` 自动带上；无需改动 |
| 附 | 上线缓存 | 改完 `js/` 必须跑 `python3 build-single.py` 刷新 `index.html` 资源 `?v=` 版本号 |

**致命风险（必须理解，否则 42 行回填成果会在最后一步被抹掉）**：若 `normalizeRecord` 把缺失字段填成 `''`、`toRow` 又无条件写列，则**恢复一份旧 JSON 备份**会走 `restoreJSON → normalizeRecord → Store.save() → pushRows → toRow`（`restoreJSON` 是**同键合并**，按 `Score.key` 命中则 `cur[j] = rec` **整体替换命中行**并继承 `id/ts/_cid`，未命中才 `push`），把云端 42 行已回填的 `exam_ym` 全部清成空串。同理，**部署窗口内持有旧内存副本的浏览器**若有未推送改动，也会用旧记录 `toRow` 回写；依赖 `fromRow` 产生 `undefined`（而非 `''`）才能省略该列、保住云端回填值。对应验收：**V-F3**（新增）。

> **口径澄清（ARCH-v3 §1.3 执行语义补充 / §7 测试护栏，避免 QA 误判）**：
>
> 1. **备份范围决定回退路径**：恢复一份不含 `examYm` 的**完整**旧备份（覆盖全部行）→ 全序列缺年月 → 走 **V-D1**（`legacySortByTs`，与旧行为逐字一致）；恢复**部分**备份（只覆盖部分行）→ 混合序列 → 走 **V-D2**（无年月排末尾、不参与趋势首/末）。
> 2. `restoreJSON` 触发的写穿属于**用户主动写操作**，按既有 `toRow` 机制会刷新 `updated_at / last_editor`，这是现状行为，**不计入 V-H2 违规**——V-H2 只约束「42 行一次性回填」这一个动作。V-F3 要守住的是「云端 `exam_ym` 不被清空」。
> 3. `fp` 纳入 `examYm` 后，恢复旧备份时 `fp(local=undefined) ≠ snap('2026-10')`，会比现状**多触发一次 update**（正确实现下 `toRow` 省略 `exam_ym`，云端年月保住、仅两列刷一次）。`pullChanges` 是 `Store.data.records = next` + `snap = snapshot()` 整体重置，**不会形成 ping-pong 无限回写**。「多一次 update」属预期，**QA 不得据此报回归**。
> 4. `tools/smoke-v2-students-classes.js` / `qa-750.js` 的夹具全部不带 `examYm`，其 `:274`「perExam 顺序 = 最早录入升序」、`:290`「perStudent 最近一次 = 期末考试」断言必须**原样通过、不改夹具**（§7 测试护栏）。

## 6. 排序与展示规则表

### 6.1 排序键（唯一真源）

```
组内代表年月 Key(学校|班级|考试) = 该组所有记录中最小的有效 examOrderKey(r).num
                                  （全组缺年月 → 走旧逻辑 legacySortByTs：最早 ts）

排序比较（Score.examCmp，在「学校|班级」内）：
  1) has=true 优先于 has=false     // 缺年月 num=+Infinity，混合时排末尾，见 OQ-3
  2) examOrderKey.num 数值升序     // year*12+month，跨年正确，禁止文本序
  3) exam 中文序 U.zh 升序         // 同年月多场考试的稳定次序
  4) ts（录入时间）升序            // 兜底
  5) id 升序                       // 最终兜底，保证多次渲染稳定
  6) 同一考试内：得分率降序 → 总分降序 → 姓名升序   // 现状不变
```

- **两个层级都要用同一把键**（避免只改总表、趋势仍错）：
  - **记录级**（某学生的考试序列、趋势图 x 轴、分析报告 `trend.exams`）→ **`Score.sortByExam(rows)`**：按每条记录自身 `examYm` 的 `examOrderKey(r).num` 排序，同年月按上表 3)–5) 兜底。所有 `studentRows` 必须走这一支。
  - **分组级**（总表「学校|班级|考试」组的先后）→ **`Score.sort(list)`**：用「组内最小有效 `examOrderKey(r).num`」作为该组代表年月；同组内各行再按 6) 排序。
  - ⚠ `Score.sort` 是分组排序（先按 school/cls 分组编序号），**不能**拿它当「某学生的考试序列」用——这正是「只改总表那一层、趋势仍错」的根因。
- **全序列缺年月**：`hasAny=false` → `legacySortByTs(arr)`（现有 `Score.sort` 原文抽出），**一行行为都不变**；golden diff 对 42 行生产快照逐行比对为空。
- 「本次 / 上次」语义：序列 `arr` 按上述升序后，`last = arr[n-1]`、`prev = arr[n-2]`；`first = arr[0]`。所有消费点统一。
- 统一改造点：`Score.sort / Score.options` 的 exams 数组、查询分析 `studentRows`、班级统计分组、`analysis.js trend.exams`、`core.js Score.history`、`locator.js` 的「上次」、`module-classes.js perStudent`、`charts.js` 的 labels 数组。
- 权威函数签名（ARCH-v3 §2.1）：`Score.examYmOf / examOrderKey / sortByExam / examCmp / examYmLabel / examAxisLabels / defaultExamYm / makeExamYm`。

**⚠ 班级分析 `timeOf()` 三用途必须分离（ARCH-v3 §1.3 #24 / §5 V3-4，防工程师一刀切）**：线上 `module-classes.js` 的 `timeOf()` 同时承担三件事，只有 ② ③ 改年月序，① **必须原样保留**，否则同一场考试的多行会被拆成两次：

| # | 用途 | 现状 | 本次处置 |
|---|---|---|---|
| ① | 同一考试多行去重（取哪一行） | 按最新 `entered_at` | **不变**（身份判定，与排序无关） |
| ② | 考试分组次序 | 组内最小 `timeOf` | 改为组内**最小有效 `examOrderKey(r).num`**，无年月排末尾，同值按 §6.1 的 3)–5) 兜底 |

### 6.2 趋势图 x 轴文案规则（单行文本、长度控制）

| 情形 | 标签 | 示例 |
|---|---|---|
| 序列内所有考试同一年，且不存在同一年月多场 | **保持现有 `exam` 原文，一字不改** | `10月段考`、`11月段考` |
| 序列内出现 ≥2 个不同年份（跨年） | `YY年·` + exam 原文 | `25年·期末考`、`26年·一模` |

| 记录缺年月 | `未标注·` + exam 原文 | `未标注·期中` |

- **统一长度上限 8 个全角字符（含前缀与分隔符）**；超出时保留 exam 原文前若干字 + `…`（如 `25年·第一次模拟考试…`）。
- 每个 x 轴 `<text>` 挂 `<title>`：`YYYY-MM · exam 原文`，解决截断后的信息损失（hover 可见）。实现方式（ARCH-v3 §2.1 / §5 V3-3）：标签由 **`Score.examAxisLabels(rows)`** 生成 `[{label, title}]`；`charts.js` 新增**可选** `opt.labelTitles`，在 `<text>` 下挂 `<title>`（内容 `U.esc`）；`labels` 仍是字符串数组，**API 向后兼容**，不改动现有调用方。
- 图表标题下方保持现有「得分率(%)」等标注，不新增图例块（避免挤压绘图区）。

### 6.3 分析报告「四、趋势」

| 元素 | 口径 |
|---|---|
| 首考试 / 末考试 | 年月升序序列的 `exams[0]` / `exams[n-1]` |
