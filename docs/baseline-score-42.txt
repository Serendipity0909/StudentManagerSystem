## 口径 A（沿用 v2，用于跨版本对照）

```sql
SELECT count(*) AS n, md5(string_agg(k,'|' ORDER BY k)) AS fp
FROM (
  SELECT stu_name||'~'||coalesce(school,'')||'~'||coalesce(class_name,'')||'~'||coalesce(exam,'')||'~'
      ||coalesce(scores::text,'')||'~'||coalesce(ranks::text,'')||'~'
      ||coalesce(total_rank::text,'')||'~'||coalesce(entered_at::text,'') AS k
  FROM score_records
) t;
```

## 口径 C（强制补充：覆盖全部既有 16 列，显式排除新增列 exam_ym）

```sql
SELECT count(*) AS n, md5(string_agg(t, E'\n' ORDER BY t)) AS fp
FROM (
  SELECT concat_ws('|', id::text, coalesce(owner_id,''), coalesce(owner_name,''),
                        coalesce(last_editor,''), coalesce(rec_id,''), coalesce(stu_name,''),
                        coalesce(school,''), coalesce(class_name,''), coalesce(exam,''),
                        coalesce(scores::text,''), coalesce(ranks::text,''),
                        coalesce(total::text,''), coalesce(total_rank::text,''),
                        coalesce(entered_at,''), coalesce(created_at::text,''),
                        coalesce(updated_at::text,'')) AS t
  FROM score_records
) s;
```

## 验收要求（V-H1 / V-H2）

改造完成（ADD COLUMN + 定点回填）后重跑口径 A 与口径 C：

1. `n` 必须仍为 **42**
2. 口径 A `fp` 必须仍为 `d08aab5b7f0aa8028873f67bd0248859`
3. 口径 C `fp` 必须仍为 `4120b89db2e0df7be40c564f7e41b70b`
4. `entered_at / updated_at / last_editor` 三列逐行与 `backup-pre-v3.json` 相等（V-H2）
5. `exam_ym` 分布：`2026-10` = 41 条、`2026-11` = 1 条
6. 唯一索引定义不变、RLS 4 条策略不变

**任一不符 = 既有列被改写，立即回滚，禁止上线。**
（备份双留证：`docs/backup-pre-v3.json` 逐行 16 列 + 本文件指纹。）

## 踩坑记录

- `scores` / `ranks` 是 **jsonb**，必须用 `::text`，不能用 `array_to_string`。
- 指纹**绝不能包含 `exam_ym`**，否则「基线无列 / 改造后有列」必然假报警。
- 回填只能 `SET exam_ym` 单列，禁止经 `sync.js toRow` 全列 upsert（会改写 updated_at/last_editor）。
- 不同拼串口径的 md5 不可互比（口径 A / B / C 各自独立）。
