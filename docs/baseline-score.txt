## 口径 A（team-lead 采集，改版前留证 · 权威）

- 采集时点：**2026-11-10 16:17 CST**，此时 `js/` 全部仍为 11-04 时间戳，7 张新表尚未创建。
- 拼串：`stu_name ~ school ~ class_name ~ exam ~ scores::text ~ ranks::text ~ total_rank ~ entered_at`
- 聚合：`string_agg(k,'|' ORDER BY k)` → `md5`

```sql
      ||coalesce(scores::text,'')||'~'||coalesce(ranks::text,'')||'~'
```


## 口径 C（v3 强制补充：全 16 列，显式排除新增列 exam_ym）

> ⚠ **规范形式唯一**：以下 `concat_ws('|', ...)` + `string_agg(t, E'\n' ORDER BY t)` 为本基线唯一认可写法，
> 结果 `4120b89db2e0df7be40c564f7e41b70b`。任何改用 `concat_ws('~')` / `string_agg(k,'|')` 的变体
> 会得到另一个 md5（实测 `e921c0705b192253d4ebaa31d73518ed`），**不同拼串口径的 md5 不可互比**，
> 照抄变体再与本值比对必然假失败并误触发回滚。

```sql
SELECT count(*) AS n, md5(string_agg(t, E'\n' ORDER BY t)) AS fp
FROM (
  SELECT concat_ws('|', id::text, coalesce(owner_id,''), coalesce(owner_name,''),
                        coalesce(last_editor,''), coalesce(rec_id,''), coalesce(stu_name,''),
                        coalesce(school,''), coalesce(class_name,''), coalesce(exam,''),
                        coalesce(scores::text,''), coalesce(ranks::text,''),
                        coalesce(total::text,''), coalesce(total_rank::text,''),
                        coalesce(entered_at,''), coalesce(created_at::text,''),
                        coalesce(updated_at::text,'')) AS t
  FROM score_records
) s;
-- n=42  fp=4120b89db2e0df7be40c564f7e41b70b
```

## 回滚方案

- 事务内任一断言失败 → `ROLLBACK`（Postgres 的 `ALTER TABLE` 是事务性的）。
- 已提交、前端发布前发现 → `ALTER TABLE score_records DROP COLUMN exam_ym;`（唯一改动就是这一列，删除即精确还原；既有列从未被写）。
- 前端发布后 → 不再 DROP（用户可能已录入新年月），走前向修复；整库回退用 `docs/backup-pre-v3.json` 经 SQL 定点还原，**禁止**用 `restoreJSON` 全列 upsert（会改写 `updated_at/last_editor`）。

## v3 踩坑补记

- 指纹**绝不能包含 `exam_ym`**，否则「基线无列 / 改造后有列」必然假报警。
- 回填只能 `SET exam_ym` 单列，禁止经 `sync.js toRow` 全列 upsert。
- 不同拼串口径的 md5 不可互比（口径 A / B / C 各自独立；口径 C 还存在易混淆的变体，见上方 ⚠）。
- `scores` / `ranks` 是 **jsonb**，必须 `::text`，不能用 `array_to_string`。
- 复算 fp 依赖 `TimeZone=PRC`；换成 UTC 会让 `updated_at::text` 变值。
