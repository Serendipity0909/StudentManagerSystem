## 1. 背景与目标

**一句话：** 把只做成绩登记的单一工具，扩成覆盖「成绩 → 学生 → 班级 → 客户 → 日常 → 合同」全链路的教务管理平台，且**不迁移、不改动任何已登记的成绩数据**。

三个正交目标：

1. **数据不断链**：成绩数据 0 丢失、0 改结构；新增模块以「弱关联」挂到成绩之上，而非重构成绩。
2. **一库共享**：所有模块数据存云端，多人登录看到同一份；沿用现有写穿 + 定时拉取的同步机制，不引入本地模式。
3. **权限收口**：仅两种身份（管理员 / 非管理员），导航隐藏 + 直接访问拦截 + 写入层校验三层到位，管理员看不到成绩，非管理员看不到教务。

### 1.1 与现有系统的边界（明确不动的部分）

| 对象 | 处置 |
|---|---|
| `score_records` 表结构与业务唯一键（姓名 + 学校 + 班级 + 考试） | **完全不改**，不新增列、不加外键 |
| `js/core.js` 的成绩算法（`Score.fields/total/rankOf/stat/upsert/sort`） | **完全不改** |
| 成绩管理 4 个 Tab（录入 / 总表 / 查询分析 / 班级统计） | 交互与口径**保持不变**，只增加角色可见性开关 |
| `js/analysis.js` / `study-plan.js` / `locator.js` / `charts.js` / `export.js` | 复用，不改口径 |
| `user_profiles`（`user_id` / `phone` / `role` / `name` / `status`，代码以 `phone` 读写） | 保留；`role` 仍只用 `admin` 与非 `admin` 两态 |
| 账号管理（`module-users.js`） | 保留现状（仅管理员可见），不扩权 |
| 同步层 `js/sync.js` 的写穿 / 拉取 / 冲突策略 | 保留机制；新增表沿用同一套 push/pull 模式 |

> **唯一的「变更」而非「新增」**：`index.html` 顶栏的「生成示例数据 / 备份导出 / 恢复导入 / 清空数据」四个按钮只作用于成绩数据，改版时纳入权限体系统一治理。
> 口径演进：**T6** 反转了成绩模块的角色限制（管理员与教师同权，前三按钮对 `canEdit()` 账号均可见）；
> **T8** 又把不可撤销的「清空数据」升为管理员专属，并要求手动输入确认词「清空」。详见 §2.1 的顶栏按钮表。

## 2. 权限矩阵

**口径（T6 反转后的最终口径，已确认，不再假设）：** 系统只有一个管理员身份，判定依据沿用现有 `App.Sync.isAdmin()`（`profile.role === 'admin'`）。

- **管理员**：概览 + 成绩管理 + 六个教务板块，**全部可见可用**（T6 起成绩管理对管理员完全放开，不再有「管理员不见成绩」的限制）。
- **非管理员（教师）**：**只能用成绩管理**，教务板块与概览一律不可见、不可达。
- **账号状态**（`status`）是叠加在角色之上的第二道门，`readonly` / `blocked` / `deleted` 一律不可写。

### 2.1 功能级矩阵

| 模块（id） | 管理员 admin | 非管理员（教师） | 导航可见 | 可写 | 拦截方式 |
|---|---|---|---|---|---|
| 概览（`home`） | 可见 | **不可见 / 不可访问** | 管理员 only | 只读（无写操作） | `adminOnly` |
| 成绩管理（`score`） | **可见、可访问、可读写**（T6 起） | 可见、可访问、可读写（`readonly` 账号只读） | 双方 | 管理员 + 教师（受 `canEdit()` 约束） | `assertWrite('score')`：只看账号状态，**不看角色** |
| 学生管理（`students`） | 可见可写 | 不可见 / 不可写 | 管理员 only | 管理员 | `adminOnly` + `assertWrite` |
| 班级管理（`classes`） | 可见可写 | 不可见 / 不可写 | 管理员 only | 管理员 | `adminOnly` + `assertWrite` |
| 客户管理（`customers`） | 可见可写 | 不可见 / 不可写 | 管理员 only | 管理员 | `adminOnly` + `assertWrite` |
| 日常工作（`tasks`） | 可见可写 | 不可见 / 不可写 | 管理员 only | 管理员 | `adminOnly` + `assertWrite` |
| 合同确认（`contracts`） | 可见可写 | 不可见 / 不可写 | 管理员 only | 管理员 | `adminOnly` + `assertWrite` |
| 账号管理（`users`，界面名「权限管理」） | 可见；仅可操作他人 | 不可见 | 管理员 only | 管理员 | `adminOnly` + `assertWrite` |

**顶栏 4 个成绩相关按钮（T6 / T8 口径）：**

| 按钮 | 可见条件 | 执行前守卫 |
|---|---|---|
| 生成示例数据 / 备份导出 / 恢复导入 | `canEdit()`（管理员与 `active` 教师都能看到） | `assertScoreAction()` |
| 清空数据 | **`isAdmin() && canEdit()`**（管理员专属，T8） | 首行 `assertAdminWrite('score')` + 弹窗内必须输入确认词「清空」 |

> 「当前无教师专属模块」是 T6 之后的既成事实：`teacherOnly` 机制保留在代码里（`perm.js` 的 `TEACHER_MODULES` 为空对象、`registerModule` 仍接受该标记），但已没有任何模块声明它，因此「该模块仅对教师开放」这类 403 文案当前不可达。

**账户状态（`user_profiles.status`）与角色的叠加规则**（沿用现有）：

| status | 能否登录 | 能看到什么 | 能否写 |
|---|---|---|---|
| `active` | 能 | 按角色 | 能 |
| `readonly` | 能 | 按角色 | **不能**（所有模块只读，按钮置灰，提交拦截） |
| `blocked` | 能但全屏拦截 | 无 | 无 |
| `deleted` | 不能 | 无 | 无 |

### 2.2 拦截分层（L1–L4，缺任一层视为不合格）

> 归为三类能力：**导航隐藏（L1）** + **直接访问拦截（L2 / L3）** + **写入层校验（L4）**。

| 层 | 位置 | 行为 |
|---|---|---|
| L1 导航隐藏 | `app.js` `navHTML()` / `navList()` 过滤 | 模块声明 `adminOnly` / `teacherOnly`，不满足则**不渲染导航项**（`teacherOnly` 当前无模块使用）；「更多模块（规划中）」分组仅管理员渲染 |
| L2 路由兜底 | `app.js` `pickModule()` | 目标模块无权限 → 回退到「当前角色允许的第一个已实现模块」：**管理员 → 概览，教师 → 成绩管理** |
| L3 直达拦截 | `hashchange` + 模块 `render()` 首行自检 | 地址栏直输 `#/students` 等 URL（`directAccess`）不回退，输出 403 卡片（复用 `.card` + `.empty` 视觉） |
| L4 写入校验 | 所有保存动作入口 | 三档守卫：`assertScoreAction()`（只判 `canEdit`）、`assertWrite(id)`（`canEdit` + 角色，`score` 只看 `canEdit`）、`assertAdminWrite(id)`（`canEdit` + `isAdmin`，用于不可撤销操作）。不通过 → toast「无操作权限」并中止 |

**403 卡片文案（统一）**：`该模块仅对管理员开放。如需使用请联系系统管理员。`

> T6 起成绩管理不再有 403 路径（管理员与教师同权），能触发 403 的只剩「管理员专属模块 × 教师账号」；文案里的角色词由 `App.Perm.ownerRoleText()` 生成，目前恒为「管理员」。

### 2.3 导航顺序

**管理员视角**（`home` 优先 → `order` 升序 → `id` 字典序兜底）：

`概览(0) → 成绩管理(5) → 学生管理(10) → 班级管理(20) → 客户管理(30) → 日常工作(40) → 合同确认(50) → 权限管理(无 order，排最后)`

**教师视角**：只有 `成绩管理` 一项（概览是 `adminOnly`，教师看不到）。

> `registerModule` 支持 `order`（数字，缺省按 100 排）、`teacherOnly`（布尔，当前无模块使用）、`adminOnly`、`visible`、`home`、`hidden`、`ready`。排序比较器 `navCompare` 必须是**严格反对称**的（`cmp(a,b) === -cmp(b,a)`），并以 `id` 字典序兜底保证可复现（T7 修复）。

### 3.2 学生管理（`students`）

**列表页**：KPI 行（学生总数 / 覆盖学校数 / 覆盖班级数 / 本月新增）+ 筛选栏 + 表格。
**筛选**：关键字（姓名，支持中文输入法安全触发）、学校、年级、班级、上课科目、上课老师；「清空筛选」按钮。
**排序**：默认 录入时间倒序；表头可点按 姓名 / 学校 / 年级 排序。

#### 字段表

| 字段 | 类型 | 必填 | 校验 | 说明 |
|---|---|---|---|---|
| 姓名 | 文本 | 是 | 去首尾空格，1–20 字 | 业务键之一 |
| 学校 | 文本 | 是 | 1–40 字 | 业务键之一 |
| 年级 | 下拉 | 是 | 枚举：小学一~六、初一~初三、高一~高三 | 业务键之一 |
| 联系方式 | 文本 | 是 | `/^[0-9\-]{7,20}$/`，11 位必须以 1 开头 | 手机或座机 |
| 系统录入时间 | 时间戳 | 自动 | 只读 | 创建时写入，永不变更 |
| 上课科目 | 多选 | 是（≥1） | 语文/数学/英语/物理/化学/生物/政治/历史/地理 + 其他 | 与成绩模块 9 科对齐 |
| 上课老师 | 多选 + 可手填 | 是（≥1） | 从账号档案昵称下拉多选，或手填文本 | 手填值不落库为账号 |
| 所属班级 | 多选 | 否 | 选项来自班级管理 | 与学生侧/班级侧**双向同一份数据** |
| 最后修改人 / 更新时间 | 自动 | — | 只读 | 列表不展示，详情展示 |

#### 操作流

- **新增**：弹窗「新增学生」，字段如上；保存前查重 `姓名 + 学校 + 年级`；命中则**阻止新增**，提示「已存在同名同校同年级学生，请前往该档案修改」（见 OQ-2）。
- **修改**：行内「编辑」→ 同一弹窗；`created_at` 只读置灰。
  - **关键异常提示**：若修改了**姓名或学校**，且成绩模块存在按「旧姓名 + 旧学校」匹配的记录（≥1 条），保存前弹确认：「本次修改后，之前按『旧姓名 + 旧学校』匹配的 N 条成绩记录将不再关联到该学生，班级成绩分析可能无法匹配。是否继续？」，默认「取消」。
- **删除**：二次确认，文案必须写明「将从 X 个班级中移除该学生；**成绩数据不受影响、不会被删除**」。删除同时清理 `class_members` 归属。
- **查询**：筛选即时生效（输入法组合期不触发，沿用 `U.onCommitted`）；无结果显示空态。
- **查看详情**：抽屉/弹窗展示全部字段 + 所属班级列表 + （P1）该生成绩趋势入口。

#### 空态与异常

| 场景 | 表现 |
|---|---|
| 无任何学生 | 「还没有学生档案。点右上『新增学生』开始，或从班级管理里添加学生。」 |
| 筛选无结果 | 「没有符合条件的学生」+「清空筛选」按钮 |
| 云端写入失败 | 顶部同步状态显示「同步失败 · 请重试」，toast 提示，改动保留内存并自动重试（沿用现有机制） |
| 无权限直达 | 403 卡片 |

### 3.3 班级管理（`classes`）

**列表页**：班级卡片网格（复用 `.grid .g3` + `.card`），每卡显示：班级名称、班级老师、课室、上课时间（多条）、学生数、年级/科目标签；卡片底部 3 个按钮：`详情` / `编辑` / `删除`。

#### 字段表

| 字段 | 类型 | 必填 | 校验 | 说明 |
|---|---|---|---|---|
| 班级名称 | 文本 | 是 | 1–30 字，**全局唯一** | 重名阻止并聚焦 |
| 班级老师 | 多选 + 手填 | 是（≥1） | 同「上课老师」 | 设置班级老师 |
| 课室 | 文本 | 否 | ≤20 字 | 如「302」 |
| 上课时间 | 结构化多行 | 是（≥1） | 星期 1–7 + 开始/结束时间，`start < end` | 展示为「周二 18:30–20:30」；同一班可多条 |
| 年级 | 下拉 | 否 | 同学生年级枚举 | 仅用于筛选与默认值 |
| 科目 | 下拉 | 否 | 9 科 + 其他 | 仅用于筛选与标签 |
| 学生数 | 派生 | — | 只读 | `class_members` 计数 |
| 创建时间 / 更新时间 | 自动 | — | 只读 | — |

#### 详情页（Tab 结构）

**Tab ①：班级学生（默认）**
- 学生列表：姓名 / 学校 / 年级 / 联系方式 / 上课科目 / 上课老师 / 操作。
- 查询：姓名关键字 + 年级筛选。
- **添加入班**：弹窗「从学生管理选择」（支持姓名/学校/联系方式搜索，多选平铺），或「新建学生并加入」（复用学生新增表单，保存后同时写入 `students` 与 `class_members`）。
- **修改学生个人信息**：弹窗内编辑学生档案字段 → 保存后**写回学生档案（`students`）**，因此**学生管理列表立即同步显示最新值**（同一份数据，非副本）。
- **从班级删除**：二次确认，文案固定：「将从本班移除该学生，**不会删除学生档案**，该生仍在『学生管理』中。是否继续？」→ 仅删 `class_members` 记录。

**Tab ②：成绩分析**
- 数据来源：本班学生 → 按 `姓名 + 学校` 匹配成绩记录（**弱关联，见 6.5**），不要求成绩记录的 `班级` 字段与本班同名。
- 输出：
  - KPI：可分析学生数 / 涉及考试场次 / 匹配到成绩的学生数 / 未匹配学生数。
  - 每场考试一行：参考人数、班均总分、最高、最低、及格率、平均得分率。
  - 科目维度：9 科班均分 / 得分率 / 及格率（条形图，复用 `App.Chart`）。
  - 学生维度：每人最近一次总分、得分率、班内排名、较上次变化（↑↓→）。
- 空态：
  - 班内无学生：「本班还没有学生，请先在『班级学生』中添加」。
  - 有学生但匹配不到成绩：「本班学生尚未录入成绩（匹配口径：姓名 + 学校）。请先到『成绩管理』录入。」

**Tab ③：班级设置**（可选，或直接在编辑弹窗做）— 建议并入「编辑」弹窗，不单开 Tab。

#### 空态与异常

| 场景 | 表现 |
|---|---|
| 无班级 | 「还没有班级。点右上『新增班级』创建第一个班级。」 |
| 班级名重复 | 输入框下方红字「该班级名称已存在」 |
| 上课时间缺失或不合法 | 阻止保存，定位到该行 |
| 删除班级 | 二次确认：「删除班级不会删除班内学生的档案和任何成绩数据。」删除同时清 `class_members` |
| 学生已被别的班加入 | 允许（多班归属），提示「该生已在 X 班」 |

### 3.4 客户管理（`customers`）

> **硬规则：客户数据与学生数据互不互通。** 不建外键、不做同步、缴费不自动生成学生档案、姓名/电话不与 `students` 做查重联动。两处出现同名客户与学生属正常现象。

#### 字段表

**基础信息**

| 字段 | 类型 | 必填 | 校验 | 说明 |
|---|---|---|---|---|
| 学生姓名 | 文本 | 是 | 1–20 字 | 业务键之一 |
| 学校 | 文本 | 是 | 1–40 字 | — |
| 联系电话 | 文本 | 是 | `/^1\d{10}$/`（客户场景强制 11 位手机） | 业务键之一 |
| 年级 | 下拉 | 是 | 同学生年级枚举 | — |
| 客户资源类型 | 下拉 | 是 | 枚举：转介绍 / 上门咨询 / 电话咨询 / 网络留资 / 地推 / 老生续报 / 其他（P2 可配置） | 分类统计维度 |
| 录入时间 | 时间戳 | 自动 | 只读（见 OQ-5） | **总资源数与周期归属的基准字段** |

**意向与跟进**

| 字段 | 类型 | 必填 | 校验 | 说明 |
|---|---|---|---|---|
| 意向产品 | 下拉 | 是 | 一对一 / 班课 | — |
| 意向科目 | 多选 | 是（≥1） | 9 科 + 其他 | — |
| 预约上门时间 | 日期时间 | 否 | 不早于录入时间（仅提示，不阻止） | — |
| 是否上门 | 布尔 | 是 | 默认「否」 | — |
| 上门时间 | 日期时间 | 条件必填 | 「是」→ 必填且不得早于录入时间；「否」→ 自动置空禁用 | — |
| 测试情况 | 下拉 | 是 | 未测评 / 优秀 / 良好 / 一般 / 待提升 | — |
| 建议班型 | 下拉 | 否 | 一对一 / 小班(2–6人) / 大班(7人以上) / 待定 | — |

**成交**

### 3.6 合同确认（`contracts`）

#### 3.6.1 价目维护（Tab ③，管理员可输入新增）

> **T9 改造**：价目由「年份×年级×阶段×连报方案」的细粒度行改为**一个报读方案一行**。
> 用户口径：家长报的是「寒春连报」「单报春季」这类**方案**，方案的阶段次数与资料费属于方案本身，
> 不应该在登记时逐行填。旧口径（阶段 + 连报方案枚举）已废弃。
>
> **T11 改造**：方案增加**备注**（选填，≤200 字，云端 `contract_prices.remark`）；备注显示在价目列表
> 与合同明细单里，并随合同快照进 `items.plans[].remark`。价目列表新增「备注」列（超 24 字截断，
> 悬浮 `title` 显示全文）。

| 字段 | 类型 | 必填 | 校验 | 说明 |
|---|---|---|---|---|
| 年份 | 数字 | 是 | 整数，2000–2100，**可新增**（如 2027） | 唯一键之一 |
| 年级 | 下拉 | 是 | 小学一~高三 | 唯一键之一 |
| 方案名称 | 文本 | 是 | 1–20 字，`trim` 后非空，**同年份年级内唯一** | 唯一键之一，如「寒春连报」「单报春季」 |
| 课时费原价 | 数字 | 是 | > 0，2 位小数，单位「元/科目/次课」 | 同一方案所有阶段共用一个单价 |
| 阶段配置 | 多行表格 | 是 | ≥1 行；阶段不可重复；次数为 1–200 整数；资料费 ≥0（可填 0） | 每行 = 阶段 + 上课次数 + 单季度单科目资料费 |
| 报读优惠 | 单选 + 数值 | 是 | 无 / 折扣（1–100 的整数百分数，85 表示 85 折）/ 减免金额（> 0） | 优惠只作用于课时费；落库存折扣系数（0.85） |
| 备注（T11） | 多行文本 | 否 | `trim` 后 ≤200 字（按 trim 后长度计） | 只展示，不参与计价；随合同快照 |

- 唯一键：`年份 + 年级 + 方案名称`（云端 `uk_prices_key`）；重复时提示「该年份年级下已有同名方案」。
- 阶段配置交互：`+ 添加阶段` 追加一行（自动挑一个未用过的阶段）、`删除` 移除一行（至少保留 1 行）；
  同一阶段填两次直接拦下「X 阶段重复配置，请合并为一行」。
- **预览行**（表单内实时）：假设**每个阶段各报 1 科**，显示 `单价 × (Σ阶段次数) × 1 + 资料费 − 优惠`
  的试算过程与结果，例如「240.00 元/次 × 25 次 × 1 科 = 6000.00 → 减 300 元 → 折后 5700.00
  → 资料费 200.00 → 应付 5900.00 元」。
- 操作：`新增方案` / 行内`编辑` / `删除`（二次确认）。编辑时唯一键排除自身，改名不误报重名。
- 展示：按 年份 → 年级 分组；每个方案一行，列为
  `方案名称 / 阶段组合摘要（A 7次 + B 18次）/ 课时单价 / 优惠摘要（85折 · 减300元 · 无优惠）/ 备注 / 操作`。
  备注为空时该格显示灰色「—」。
- 空态：「该年份还没有价目方案，点『新增方案』录入」；同一分组下无方案也不留空白分组。

#### 3.6.2 合同登记（Tab ①）

> **T11 改造（用户实际使用后的反馈）**：一张合同**可以同时报多个方案**（如「寒春连报」+「暑期班」），
> 报读方案从单选下拉改为**勾选框多选**；每个被勾选的方案渲染一个独立方案块，
> 各自选科目、各自设优惠；电子账户结余仍然**整单一个**。

**输入区（自上而下）**

1. **学生姓名**（文本，必填，≤20 字）+ **合同年级**（下拉，必填）。姓名输入时从学生档案联想（下拉候选，**仅辅助，不强绑定**）。姓名+年级已存在合同时，弹提示「该学生在 X 年级已有合同，是否打开修改？」。
2. **合同年份**（下拉，默认当前年；选项来自价目维护里已存在的年份）。
3. **报读方案**（**勾选框，可多选，至少 1 个**）：列出 `年份 + 年级` 命中的全部方案，每个选项标签形如
   `寒春连报（A 7次 + B 18次 · 240.00元/科 · 85折）`。**勾选后阶段次数、资料费、单价全部带出，登记页不可改价目**。
   一个都不勾时显示「至少勾选 1 个报读方案」并禁用保存。该年份年级下没有任何方案时提示
   「该年份年级还没有价目方案，请先到『③ 价目维护』新增」。切换年级/年份时清空已勾选的方案（需重选）。
4. **每个被勾选方案的方案块**（按价目列表顺序渲染，勾选顺序不改变顺序）：
   - 块头：方案名 + **每阶段的摘要 chip**，文案 `A 阶段·7 次·资料费 100.00 元/科`（一个阶段一个 chip）；
     优惠被手动改过时额外显示 `已手动调整优惠` chip。
   - 块内：按**该方案定义的阶段**分块（方案只有 A、B 就只渲染 A、B 两块），每块一个科目多选，**每块至少 1 科**，
     计数 chip 为「已选 N 科」/「至少选 1 科」。
   - 块内：**该方案自己的优惠**（默认取方案预设，可覆盖），三种模式同上一条口径。
5. **优惠**（**每方案一份**，作用对象 = 该方案的课时费合计，**不含资料费**）：
   - 默认取该方案预设值；用户可手动覆盖：`原价` / `折扣（百分数输入，85 表示 85 折）` / `减免金额（元）`。
   - 一旦某方案被改成与预设不同 → toast「已手动调整优惠，与方案预设不同」（只提示，不阻止），
     且该方案的 `discountTouched` 置真（每方案独立，A 方案改过不影响 B 方案跟随预设）。
   - 折扣必须为 1–100 的整数百分数或 ≤1 的小数系数；减免金额 > 0。非法时实时红字提示，保存时同样拦截；
     多方案时提示前缀带方案名，如「方案「暑期班」：折扣需在 1–100 之间」。
6. **电子账户结余金额**（数字，选填，≥0，**整单一个**）：用于抵扣，抵扣上限 = 整单小计（Σ折后课时费 + Σ资料费）。
7. **优惠明细单**（实时生成，只读卡片）：见 3.6.3。
8. 底部：`保存合同` / `重置`。明细不完整（缺方案、缺阶段、缺科目、优惠非法）时保存按钮置灰；
   就绪时提示「已选 N 个方案 · 应付 X 元」。

**保存口径**：`contracts.plan` 存**方案名用 `+` 拼接**（如 `寒春连报+暑期班`，台账筛选按整串匹配）；
`items` 快照为 `{plans:[…], pricesVersion}`，每个方案一项，含
`planName / unit_price / stages / subjects / discount{type,value} / lines / subjectRows / stageMaterial /
original / discountAmount / tuition / materialAmount / remark`
（同时保留 T9 的平铺冗余字段 `planName / plan / stages / lines / subjectRows / stageMaterial`，
单方案时与 T9 快照逐字段等价，供老渲染路径复用）。
`contracts.discount_type` 在各方案优惠一致时沿用该类型，**不一致时取 `mixed`**（台账显示「多方案优惠」）。

#### 3.6.3 优惠明细单（必须渲染的区块，Excel 风格）

> 2. **「电子账户结余抵扣」行条件渲染**：只有真的产生了抵扣（> 0）才出现该行，没结余时**整行不出现**
>    （不是显示「—」）。
> 3. **优惠行条件渲染**：无优惠（优惠金额为 0）时整行不出现；有优惠时标签为

> 4. **多方案时逐方案分块**：每个方案一块（科目表 + 本方案 5 行小计），末尾再给一张整单合计表

>    多个方案备注**完全相同**时合并到合计表下方只显示一次。
> 6. 「该价目已变更，明细为签订时快照」chip **保留**。
>
> **T12 改造（用户第二次看实际效果的展示层反馈）**：T11 的第 4、5 条被下面两条取代，
> 其余（去公式注释、结余行/优惠行条件渲染、快照 chip）继续有效。**计价数据层零改动**，
> `priceContractMulti` / `priceEntry` / `items` 快照结构完全不变。
>
> 1. **合并横表**：方案不再各占一张竖表，**整张明细单只有一张表**（便于整屏截图发家长）：

>      `小计` = 各方案该科金额之和）→ 资料费行 →（仅多方案）方案小计行 → 整单汇总块。
>    - 科目行排序取**首次出现序**（方案顺序 → 阶段 A→D → 录入顺序）：单方案时行序与 T9 逐行一致。

>      **单价不同** → 不设单价列，改为列头 `… · 240.00 元/科`，单元格写 `240.00×7=1680.00`
>      （家长能自己复核）。
>    - **汇总块并入同一张表**（不再是表格外的第二张表）：行标签占一列并用 `colspan` 跨掉

>    - 表格 `min-width` 按列数自适应，超出容器宽度时**容器横向滚动**（弹窗本身不横向撑破）。

## 6. 关键计算规则

### 6.1 客户统计口径

**周期定义（本地时区，含首含尾）**

| 周期 | 区间 |
|---|---|
| 当周 | 本周一 00:00:00 – 本周日 23:59:59.999 |
| 当月 | 当月 1 日 00:00:00 – 当月最后一日 23:59:59.999 |
| 本年 | 1 月 1 日 00:00:00 – 12 月 31 日 23:59:59.999 |

**每个指标用自己的时间字段归属区间（不可混用）**

| 指标 | 判定 |
|---|---|
| 总资源数 | `created_at ∈ 区间` 的客户记录数 |
| 上门资源数 | `visited = true` 且 `visit_at ∈ 区间` |
| 签单学生数 | `paid = true` 且 `paid_at ∈ 区间` |
| 签单金额 | 上述签单记录的 `paid_amount` 求和（2 位小数） |

**比率**

```
上门率     = 上门资源数 / 总资源数
签单率     = 签单学生数 / 总资源数
上门签单率 = 签单学生数 / 上门资源数
```
- 保留 1 位小数（`xx.x%`），分母为 0 → 显示「—」（**不得显示 0% 或 NaN**）。
- 分类分析：按 `resource_type` 分组，逐组套用上述同一口径；末行合计必须等于总 KPI（可作自检断言）。

### 6.2 任务汇总口径

- **周期归属用「预期完成时间」`due_at`**；完成情况用 `status` + `done_at`。
- 每周期：计划数 = `due_at ∈ 周期` 的任务数；已完成数 = 其中 `status = done` 的数量；未完成数 = 计划数 − 已完成数；逾期数 = 其中 `status ≠ done` 且 `due_at < 现在` 的数量。
- 完成率 = 已完成数 ÷ 计划数（分母 0 → 「—」）。
- 周 = 周一至周日；月 = 自然月。
- 跨周期完成（上周的活本周干完）：**计入其 `due_at` 所属周期**（保证分母一致、完成率不超 100%）。

### 6.3 金额与四舍五入

- 一切金额内部按「分」精度计算，展示保留 2 位；**四舍五入（round half up）**，不用银行家舍入。
- 计算顺序固定：`原价 → 折扣（作用于课时费合计）→ 加资料费 → 减结余`。
- **折扣按「合计」一次性计算后再取整**，不逐科取整（避免累积误差）。
  - 反例说明：3 科各 1234.50，85 折。逐科 `1049.33×3 = 3147.99`；合计 `3703.50×0.85 = 3147.975 → 3147.98`。**以 3147.98 为准。**
- 资料费**按阶段配置**（T9：`contract_prices.stages[].material_fee`，单个阶段单科目的金额，
  可为 0；新建方案时默认填 100），**按阶段分别收取**，**永不参与折扣、不参与优惠金额抵扣**。
- 结余抵扣 ≤ 应付小计，应付金额下限 0，不出现负数。

### 6.4 合同计价公式（可直接编码）

> **T9 改造**：价目改「一个报读方案一行」后，公式写成一个**方案**上的计算：
> 方案自带阶段配置（每阶段次数 + 单科资料费）与优惠预设，登记时只选科目与（可选）覆盖优惠。
>
> **用户口径原文**：`报读费用 = 课时单价 × 具体报读次数（A次数＋B次数）× 报读科目数 ＋ 资料费（按阶段分别收取）− 优惠金额`
>
> 原文只在「各阶段科目数相同」时严格成立。实现按**逐阶段**展开（下式 O 中的 `Σ阶段`），
> 当各阶段科目数相同时与用户公式完全等价 —— 这是原公式的自然推广，不是改口径。

```
输入：
  方案 plan  = { unit_price, stages:[{stage, sessions, material_fee}], discount_type, discount_value }
  科目选择 subjects = { A:[…], B:[…], … }        // 只含方案定义的阶段，每阶段至少 1 科
  优惠覆盖 discount = { type:'none'|'pct'|'amount', value }  // 未给则用方案预设
  结余 balance

课时费原价合计  O = round2( Σ_阶段( unit_price × sessions_阶段 × 该阶段科目数 ) )
优惠            ( type=none )   T = O
                ( type=pct )    T = round2(O × k)，k 为折扣系数（85 折 → k = 0.85）
                ( type=amount ) T = round2( max(0, O − min(减免额, O)) )   // 优惠上限 = O，不出现负课时费
折扣减免        D = round2(O − T)
资料费合计      M = round2( Σ_阶段( material_fee_阶段 × 该阶段科目数 ) )
小计            S = round2(T + M)
结余抵扣        C = round2( min(结余输入, S) )
应付金额        P = round2(S − C)
结余剩余        R = round2(结余输入 − C)      // 仅提示，不落台账

科目行（明细单）：一个科目一行，跨阶段合并
  sessionsTotal = Σ(该科目所报各阶段的 sessions)
  amount        = round2(unit_price × sessionsTotal)
资料费行（明细单）：按阶段列 material_fee × 科目数，末尾合计
```

**T11 多方案聚合**（一张合同报多个方案时，上式对每个方案各算一遍，然后逐项求和）：

```
输入：plans = [ {plan_p, subjects_p, discount_p} , … ]   // 每个方案自己的科目与优惠
      结余 balance                                        // 整单一个，不按方案分摊

对每个方案 p 独立计算：O_p、D_p、T_p、M_p、S_p = T_p + M_p
  （优惠_p 只作用该方案自己的课时费，A 方案的折扣不影响 B 方案）

O = round2( Σ_p O_p )      D = round2( Σ_p D_p )
T = round2( Σ_p T_p )      M = round2( Σ_p M_p )
S = round2( T + M )
C = round2( min(结余输入, S) )
P = round2( S − C )
R = round2(结余输入 − C )
```

**取整纪律**：`O / T / D / M / S / C / P` 每一步都走 `App.UI.round2`（round half up），
折扣**对 O 一次性取整**，绝不逐科取整；多方案时先在各方案内部取整，再对汇总值取整。

#### 算例（与 `tools/smoke-v2-contracts.js` 逐条对应）

**基准方案（寒春连报）**：`unit_price = 240`，`stages = [A 7次/资料费100, B 18次/资料费100]`，无优惠。
单报春季：同单价，`stages = [A 7次/资料费100]`。

| # | 场景 | 计算 | 结果 |
|---|---|---|---|
| 1 | 寒春连报 · 1 科（数学 A+B）· 减免 300 | O = 240×25×1 = 6000；M = 100+100 = 200 | **P = 5900.00** |
| 2 | 寒春连报 · 2 科（数学/英语 A+B）· 减免 700 | O = 240×25×2 = 12000；M = 100×2×2 = 400 | **P = 11700.00** |
| 3 | 单报春季 · 1 科 · 减免 50 | O = 240×7 = 1680；M = 100 | **P = 1730.00** |
| 4 | 寒春连报 · A 报 1 科、B 报 2 科 · 85 折 | O = 240×7×1 + 240×18×2 = 10320；T = 8772；M = 100×1+100×2 = 300 | **P = 9072.00**（D = 1548） |
| 5 | 寒春连报 · 数学同时报 A、B | 合并成 1 行，`sessionsTotal = 25`，小计 = 240×25 = 6000 | **科目行 = 1 行** |
| 6 | 同 #1 但减免 99999（优惠 > 课时费） | T 截断为 0，D = 6000 | **P = 200.00**（只剩资料费） |
| 7 | 同 #1 但结余 20000（结余 > 应付） | C 封顶为 6200 | **P = 0.00**，剩余 13800.00 |
| 8 | 方案预设 85 折、不传 discount（默认带入） | T = 6000×0.85 = 5100 | **P = 5300.00** |
| 9 | 单价 1234.50、A 阶段 25 次、3 科、85 折 | O = 1234.50×25×3 = 92587.5；T = round2(92587.5×0.85) = round2(78699.375) | **T = 78699.38**（一次性取整，不是逐科的 78699.39） |
| 10 | 方案无阶段 / 一科未选 | `priceContract.ok = false`，`validateContract` 返回「A 阶段至少选择 1 科」 | **拒绝保存** |

> 算例 4 是「用户公式只在各阶段科目数相同时成立」的对照：A 报 1 科、B 报 2 科时，
> 必须逐阶段乘，若图省事写成 `240×(7+18)×2 = 12000` 就错了（差 1680）。

**T11 多方案算例**（`tools/smoke-v2-contracts.js` §11 逐条对应）：

基准：方案一「寒春连报」（O₁ = 6000、M₁ = 200、减免 300 → T₁ = 5700）；
方案二「暑期班」（`unit_price = 200`，`stages = [C 10次/资料费50]`，方案预设 85 折；
C 报 1 科 → O₂ = 2000、T₂ = 1700、M₂ = 50）。

| 项 | 计算 | 结果 |
|---|---|---|
| 整单 O | 6000 + 2000 | **8000.00** |
| 整单 D | 300 + (2000−1700) = 300 + 300 | **600.00** |
| 整单 T | 5700 + 1700 | **7400.00** |
| 整单 M | 200 + 50 | **250.00** |
| 整单 S | 7400 + 250 | **7650.00** |
| 结余 0 → P | 7650 − 0 | **7650.00** |
| 结余 1000 → C / P / R | C = 1000 | **P = 6650.00**、R = 0 |
| 结余 99999 → C 封顶 | C = S = 7650 | **P = 0.00**、R = 92349.00 |
| 只把方案一改成 5 折 | T₁ = 3000；**T₂ 仍 1700**（优惠互不影响） | 整单 D = **3300.00** |

### 6.5 班级 → 成绩的匹配口径

```
班内学生 S = class_members(class_id = 当前班级) → students
某学生成绩记录 R = score_records 中 name = S.name 且 school = S.school 的全部记录（不限定 exam）
```

- **不用** `score_records.class_name` 与本班名称匹配：前者是学生所在学校的行政班级，与本机构的教学班不是同一概念。
- 匹配不到时不计入「可分析学生数」，单独列出「未匹配」名单，便于人工核对。
- 统计全部复用 `App.Score.stat(rows, col)` / `Score.totalRate` 等现有函数，**不自造第二名次或新的及格线口径**。
