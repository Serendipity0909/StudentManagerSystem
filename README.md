# 学生管理系统（多人协作版）

用纯 JavaScript 复刻原 `学生成绩管理系统.xlsm` 的全部功能，不依赖 Excel。
数据**只保存在云端数据库**，多位老师用同一个网址登录即可共用同一批成绩。

## 老师怎么用（发给同事的话术）

1. 打开网址：<https://student-scores-36336.app.workbuddy.host/?sharecode=PLP3XNNE6N>
2. 首次进入是**独立登录页**：用手机号 + 验证码注册并设置密码（首次注册后即可用密码登录）
3. 直接用。电脑、Mac、iPad、手机浏览器都能开，**不用安装任何东西**

登录后所有老师看到同一份数据，谁录的都会实时出现在「成绩总表」里。
**未登录时不能查看或录入成绩**，一律停在登录页（数据都在云端，本机不留副本）。

## 账号、密码与权限

- **登录**：手机号 + 密码；未登录或登录失效会统一跳转到登录页。
- **忘记密码**：登录页 → 「忘记密码？用短信验证码重设」。
- **昵称**：右上角头像 → 用户设置 → 基本资料；手机号在此**只读展示**，不可修改。
- **退出登录**：右上角头像 → 退出登录；会同时清理本机会话，换人登录不会串号。
- **权限管理**：左侧菜单中的独立模块，仅**管理员**可见。权限只到账户级：

| 处理方式 | 状态 | 含义 | 可否恢复 |
|---|---|---|---|
| 限制编辑 | 只读 | 可查看全部成绩，不能录入/修改/删除 | 可 |
| 限制编辑 | 停用 | 保留账号，看不到数据也不能录入 | 可 |
| 删除账户 | 已删除 | 不可再登录；其已录入的成绩保留 | 不可 |

只读与停用是**数据库层强制**的，不是界面隐藏。

## 数据是怎么存的（纯云端）

```
页面（内存工作副本）→ 云端数据库（立即写穿）
                   ← 定时拉取（45 秒 / 切回页面时，以云端最新版本为准）
```

- **写穿**：每次录入、修改、删除都会立即写入云端，不弹窗、不排队等待。
- **换设备也看得到**：登录后自动全量拉取，换电脑、换 iPad 都能继续。
- **last-write-wins**：多人同时改同一条记录时，以云端最后一次写入为准，不再弹冲突框。
- **失败必须让用户感知**：写入失败会提示「保存到云端失败，请重试」，失败的改动留在内存里自动重试，绝不静默丢弃。
- 顶栏同步状态只有四态：**未登录 / 同步中… / 已同步 HH:MM / 同步失败 · 请重试**。
- 其他老师的修改会在 45 秒内或你切回页面时自动出现，不做任何打扰式提醒。

- **清空数据影响所有人**：点「清空数据」会逐条删除云端记录，弹窗里会明确提示这一点。建议改用单条删除。
- **生成示例数据同理**：会同步给所有老师看到，用完后记得清空。

  这个限制由数据库的行级安全策略强制，不是靠网页按钮藏起来。

**及格线改为高考口径**（2026-11 升级）：

| 项 | 口径 |
|---|---|
| 单科满分 | 语文 / 数学 / 英语 各 150 分，物理 / 化学 / 政治 / 历史 / 地理 / 生物 各 100 分 |
| 单科及格线 | 语数英 90 分，其余六科 60 分 |
| 满配满分 | 语数英 + 3 门选科 = **750 分**（`K.FULL_TOTAL`，仅供文案引用） |
| 满配及格线 | 450 分 = 750 × 60%（`K.PASS_TOTAL`） |
| 动态满分 | 由成绩自动识别：只填语数英 → 450 分（及格 270）；满配 6 科 → 750 分（及格 450） |
| 选科上限 | 选考科目有分即计入，超过 3 门取分数最高的 3 门（同分按 物理→化学→政治→历史→地理→生物） |
| 评语分档 | 按**得分率**：≥90% 优秀 / ≥80% 良好 / ≥70% 中等 / ≥60% 刚过及格线 / 其余 待加强（避免 150 分制下 90 分被当优秀） |
| 高亮 | 单科低于本科及格线（90 / 60）标红，不再统一用 60 分 |
| 趋势阈值 | 保持 ±2 / ±5 分不变；低于班均 5 分仍触发提醒 |

## 成绩分析报告（六节精简版）

查询分析页生成，章节顺序固定：

| 章节 | 内容 |
|---|---|
| 一、成绩总览 | 大号总分 `x / 动态满分`、及格线标记、得分率进度条（60% 基准 + 班均竖标）、班级/年级位次、一句话结论，以及选科构成与 overflow / 缺必考提示 |
| 二、各科表现 | 每科一行：得分/满分 + 得分率条形（60% 虚线基准 + 班均竖标），颜色语义：达标绿 / 临界琥珀 / 薄弱红；表下小字说明未计入科目（缺考 / 未选 / 超 3 门舍弃） |
| 三、位次 | 班级排名与年级排名并列 + 百分位（按得分率），百分位不可计算时显示「—」并给出核对提示；年级人数可手动覆盖 |
| 四、趋势 | 仅 ≥2 次考试展示，一条得分率折线 + 2 行结论（总分/得分率变化、进退科目） |
| 五、优势与短板 | 左右两栏卡片，各列科目 + 一句可执行动作，最多 3 条/栏；下附 3 条行动建议 |
| 六、阶段规划 | 提分目标表（科目 / 当前 / 目标 / 差距 / 一句话动作，≤5 行）+ 院校定位结论与明细 |

报告中所有「满分 / 及格线 / 占比」均使用**动态值**：不同学生选科不同，跨组合只比得分率，不比绝对分。

**年级人数来源（优先级）**：

1. **定位表**：取「届别 + 学校」匹配行的二本B上限（`tb`）近似该科类在校人数；未指定科类时物理类 + 历史类相加；
2. **联网查询**：`js/data-gradesize.js` 中各校 2025 年招生计划（整届人数），覆盖 18 所；
3. **未知**：按系统内有效人数计算百分位，并在「三、位次」提示手动填写。

数据来源：中山市 2025 年普通高中招生计划（各校招生简章汇总，2026-11 联网查询），静态存放于 `js/data-gradesize.js`，覆盖 18 所：
纪中 1739、一中 1908、侨中 1782、实验 1620、桂山 1080、永安 1458、烟洲 1620、二中 1296、博文 900、
迪茵 1120、华辰 1070、杨仙逸 648、东升 756、龙山 1080、榄中 1512、东区 920、濠头 1080、古高 540（单位：人，整届招生计划总数）。

手动覆盖输入 `#an-graden` 填入人数后写入本机本次会话的 `state.gradeN['学校|届别']`，重渲染后保持报告展开与滚动位置。

**提分方案口径**：

- **目标总分 = 批次线口径，不再用名次反推分数**（同分并列时「第 N 名的分数」不可靠，旧 `rank` / `estimate` 两个分支已删除）。批次线取 26 届高考实际数据（`js/study-plan.js` 的 `P.LINES26`）：

  | 档次 | 物理类 | 历史类 |
  |---|---|---|
  | 本科线（二本B） | 425 | 440 |
  | 二本A | 500 | 500 |
  | 特控线（重点本科） | 539 | 546 |
  | 双一流线 | 600 | 600 |
  | 985线 | 630 | 630 |

- **档次由定位表名次决定，分数取该档次的线**：`loc.ok` 时取 `nextName`（上一档）对应的批次线作为目标分，名次上限用 `nextLimit` 作为过程指标；若当前分数已越过该线（分数跑在名次前面），顺延到分数之上的最近一条线。定位表给不出档次（无排名 / 学校无数据）时，退回「分数之上的最近一条线」（`targetTotalSource = 'line'`）；已越过 985 线则转「稳线 + 冲分」（`'top'`，再 +10 分）。
- **压线口径**：总分**恰好等于**某条线时按「压线未稳」处理——该分数同分并列密集，不算已过线，目标直接落位上一档；名次**恰好等于**该档上限时同样标记 `rankOnEdge`，文案给出「再多进约 5% 名次留余量」的建议。两者都不会把「刚好踩线」当成安全。
- **科类未识别**（只录了语数英、没有物理/历史成绩）：暂按物理类批次线，并在文案中披露「历史类本科线 440、特控线 546」的差异（`trackAssumed = true`）。
- 目标总分一律 `Math.min(动态满分, 当前总分 + delta)` **硬封顶**：当前总分已达该组合满分时 `delta = 0`，文案改为「已达该组合满分，目标转为保持与单科均衡」（不再出现「目标 780 / 满分 750 / 需提高 0 分」这类自相矛盾句）；「距及格线」只在未达线时输出，不出现负值。超满分录入（历史脏数据）时报告总分按 `min(总分, 动态满分)` 展示，并在总览下方注明「检测到超满分录入，得分率已按满分截断」。
- 增量只在本生**已计入科目**内分摊，权重 `w = full_i × (1.25 − 得分率_i)`（`full_i` 为该科满分），单科不超满分，`Σ单科 delta ≡ 总 delta`（±0.01）。
- 动作库按得分率分三档（<60% 补基础 / 60-75% 题型专项 / ≥75% 拔高），每条都带频次与可验收标准。

## 院校定位（查询定位器）

院校定位内嵌在分析报告「六、阶段规划」的**院校定位明细**（`Locator.bodyHTML`，报告只有六节，不再单列章节），按**届别（班级字段）+ 学校 + 科类 + 校内总分排名**判定该生当前可报考层次：

| 项 | 规则 |
|---|---|
| 科类判定 | 物理 > 0 记物理类，否则历史 > 0 记历史类；两者都有分或都缺考时，界面给出「物理类 / 历史类」下拉由老师手选 |
| 档次判定 | 按 985 → 双一流 → 特控（重点本科）→ 二本A → 二本B 的顺序，取**第一个「上限 ≥ 排名」**的档次；上限为 0 / 空表示该校本届未划线，直接跳过 |
| 名次差 | 下一档次 = 当前档次的上一档，差距 = 当前排名 − 上一档上限；已达 985 显示「已达最高档次」 |
| 未达线 | 排名超过二本B上限（或未划线）时不推断档次，提示「当前排名暂未达到表内最低档次线」 |
| 数据缺失 | 阈值表查不到组合 → 「暂无该学校数据，无法查询」；没有总分排名 → 「暂无该学生总分排名，无法定位」 |
| 学校匹配 | 按录入的「学校」字段 **trim 后严格精确匹配**，不做任何别名/模糊猜测。阈值表内没有的学校（如迪茵、江门培英、江门棠下、江门省实）一律走「暂无该学校数据」分支；提示下方会附一行浅色的「当前支持：…」（从 thresholds 去重自动取，共 17 所） |
| 29届 | 阈值表含 29届，但该届扩招、原始数据误差较大，区块内会给出浅色备注「不建议现在给 29届 使用」，结果仅供参考 |

注意：定位器原始数据**并非严格单调**（例如 28届二中物理类 985 上限 30 而双一流上限 25），因此必须按固定顺序取首个命中，不能用「取最大上限」实现。

## 数据安全

- 数据只有云端一份，是本系统的**唯一权威副本**，请保持联网使用。
- 仍建议每月点一次顶栏「备份导出」存档 JSON（用于跨年度归档或交给学校）。
- 「恢复导入」会把备份里的记录按唯一键批量写入云端，其他老师也能看到导入结果。
- 换账号 / 重新登录前先「退出登录」：会清理会话与同步上下文，避免串号。

## 新增模块

在侧边栏往下可以看到「学生档案 / 考勤管理 / 课程课表 / 作业管理」四个规划中的占位入口。
要做成真模块时：

1. 新建 `js/module-xxx.js`；
2. 在里面 `App.registerModule({ id, name, icon, ready:true, title, subtitle, render(), bind(host) })`；
3. 在 `index.html` 里加一行 `<script src="js/module-xxx.js"></script>`。

侧边栏会自动出现入口，数据统一走 `App.Store.data.modules.xxx`，无需改动其它代码。

常用 API：`App.Score`（成绩算法）、`App.Store`（存储）、`App.U`（工具）、`App.X`（导出）、`App.Chart`（SVG 图表）、`App.Modal` / `App.Toast`（交互）。

## 重新打包单文件版

改完 `js/` 或 `assets/` 下的文件后：

```
python3 build-single.py
```

会重新生成上一级目录的 `学生管理系统-单文件版.html`，同时**自动刷新 `index.html` 里全部本地资源的 `?v=` 版本号**（缓存击穿）。
**每次发布线上前必须先跑一次构建**，否则用户浏览器可能在数小时内继续拿旧 js。
